# 蒸散量の実測値補正

## 保存と試算

補正実測先のuser_idと比較日数（1～10日、初回5日）を地点ごとの共有設定としてDBに保存する。温度・湿度はP01から取得し、植物・共通パラメータは「推定値」と共用する。風速は手入力、日射は透過率による既存計算を使う。

予報の取得成功時に、植物設定・補正設定・実測の締切日時を固定する。設定保存は次回の予報採用から有効。別端末の変更と競合した場合は保存を止め、再読込みを案内する。保存履歴は上書きしない。

過去日は保存履歴だけを表示する。履歴がなければ「保存履歴なし」とし、再計算・埋め戻しは行わない。今回取得した翌日の予報だけは現在の設定で試算できる。試算は設定・履歴を変更しない。「保存値に戻す」で当時の固定値へ戻る。

## 比較方法

採用日を最終日とするN日間を使う。10月9日に採用した10月10日予報、比較5日の場合は10月5～9日。本日の有効な実測がない時間帯・項目は1日前へずらして10月4～8日を使う。温度・湿度は独立して判断する。その他の欠測に対してさらに過去日を追加しない。

各時間帯の測定を1時間平均し、各日の前日18:10に採用済みの予報と比較する。測定1件でも使用する。複数日は日ごとに同じ重みで差を平均する。有効日数・件数・実際の期間・各日の根拠を保存し、比較表とCSVへ載せる。差を得られない項目は元の予報を使う。

温度差は℃、湿度差は％ポイントで加算する。湿度は0～100％に制限し、調整の有無を記録する。補正後の温湿度から飽差g/m³とVPD kPaを計算する。植物設定が未入力の場合は比較根拠を保存し、水量・時間は未計算とする。

## 取得失敗と再試行

最初の実測取得に失敗した場合は5分間隔で最大5回再試行する。再試行でも実測の締切は採用時のまま。正常に取得した結果が空の場合はデータ不足として確定する。全6回失敗した場合は取得失敗を記録し、元の予報で確定する。実測先未設定の場合もその理由を記録する。

取得・計算が成功した結果をジョブに保持し、履歴書込みの失敗で実測を再取得して結果を変えない。保存待ちの画面は、試算や未保存の設定変更をしていなければ1分ごとに確認する。

## 画面とCSV

温度・湿度の補正差を2グラフで表示する。平均差は太線、各日は薄線。比較表は実際の期間・有効日数・測定件数・補正後の温湿度と飽差を表示する。6本の蒸散量グラフは既存の表示を共用する。

保存履歴CSVと翌日の試算CSVを分ける。欠測は空欄と状態列で区別し、実測締切・取得状態・項目別の期間・日別の根拠も含める。期間指定の保存履歴CSVは保存済みの値のみ出力する。

## 本番への適用

追加テーブルの定義は `u-tech-next-correction-schema.sql`。作成済みの場合は再実行しない。コード反映後、補正設定を画面から保存する。既存の予報取得の定期起動に加え、同じ実行ユーザーで次の処理を毎分起動する。

```cron
* * * * * umask 0007 && /usr/bin/php /var/www/html/scripts/process-next-correction.php >> /var/lib/utech-next/correction.log 2>&1
```

ログ先は実行ユーザーが書き込める既存の運用ディレクトリを確認して使う。次回の予報採用からジョブ・補正履歴が作成される。過去の予報に対するジョブは追加しない。

## 検証

`test-next-correction.php` は比較期間・固定締切・項目別の切替・件数・湿度調整・未入力を検証する。`test-next-correction-jobs.php` は模擬DBで再試行・履歴固定・書込み失敗時の結果保持を検証する。`test-next-correction-ui.cjs` はPHPと画面計算の一致、保存値と試算、CSV、設定保存・競合、スマホ表示を検証する。本番MariaDBでの実際の保存と定期起動は反映後に確認する。
