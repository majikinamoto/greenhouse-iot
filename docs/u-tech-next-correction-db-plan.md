# 実測値補正のDB対応案

> 2026-10-09追記：過去日の「再計算しない」方針は変更。固定履歴がない日は現在の設定で画面だけ再計算する。DBへの埋め戻しは行わない。最新の動作は `u-tech-next-correction.md` と画面の「計算方法・ルール」を参照。

この文書と追加SQLは設計案。DBには未適用。既存の予報・推定値の保存処理にはまだ組み込んでいない。

## 保存先

現行Nextは代表予報地点の`location_id`をキーに植物設定と履歴を保存している。今回もこの設定対象に補正設定を対応付け、実測先は独立した`source_user_id`で選択する。将来複数の推定対象ハウスを扱う場合は、予報地点と対象ハウスを分けた識別子が必要になる。今回の追加だけで複数ハウス対応済みとはしない。

追加SQL：`docs/u-tech-next-correction-schema.sql`。既存テーブルの列変更・データ更新・過去日の再計算は行わない。

- `next_water_correction_settings`：全端末で共有する実測先ID、1～10日の比較日数、競合確認用revision、更新日時。ID未設定はNULL。設定未作成時はID未設定・5日として扱う。画面の変更だけでは更新せず、保存操作でのみ更新する。
- `next_water_correction_jobs`：予報採用時に固定した計算条件と、初回＋最大5回の取得試行状態。予報が保存済みでも、未完了の補正処理を再開するために使う。
- `next_water_correction_history`：対象日ごとの固定結果と根拠。取得時刻・実測の締切・履歴確定時刻を分けて保存する。保存済みの行は上書きしない。

JSONはMariaDBの既存方式と同じく、JSONとして妥当な値のみ保存する。`result_json`の構造の検証はアプリ側でも行う。

## 予報採用と再試行

1. 前日18:10の予報取得に成功した際、保存済みの補正設定と植物・共通設定を固定する。設定の取得に失敗した場合は、ID未設定として扱わずエラーを報告する。
2. 予報・従来の推定履歴・補正ジョブを同じトランザクションで保存する。ジョブの`context_json`には、予報25時刻、両設定とrevision、式／補正方式のバージョン、比較の基準日、対象の予報地点を含める。
3. `measurement_cutoff`は予報取得成功時刻で固定する。再試行が遅れても`recorded_at <= measurement_cutoff`の実測値だけを使う。タイムゾーンはAsia/Tokyo。実測の記録時刻を基準とするため、遅れてDBに届いた過去時刻のデータは成功した取得で読める場合がある。
4. 正常に取得できた場合は補正結果を確定する。取得成功だが実測値が空なら、データ不足として元の予報値を使用する。ID未設定は取得せず補正なしで確定する。
5. 実測取得エラーの場合、初回失敗から5分間隔で最大5回再試行する。設定・予報・締切を再取得して差し替えない。ジョブをDBに残し、プロセスの中断後も継続できるようにする。再試行起動用の定期処理も必要。
6. 6回すべて実測取得に失敗した場合は、補正なしの結果を`measurement_fetch_failed`として保存する。履歴のDB書込み失敗は実測取得失敗と区別し、履歴保存に成功するまで完了扱いにしない。
7. 履歴INSERTとジョブのcomplete更新を同じトランザクションで行う。二重起動をロックで防ぎ、既存の履歴を変更しない。

## 比較期間（合意した変更）

基準日は予報取得成功日のJST日付。例えば10月10日の予報を10月9日に採用し、比較5日なら、基本の比較期間は10月5～9日。

時間帯・項目ごとに、本日の有効な実測平均があればこの期間を使う。本日の実測がなければ期間を1日前へずらし、10月4～8日を使う。温度・湿度は独立して判断する。本日の実測はあるが比較元の予報が欠測なら、その日は差を計算できないものとして除外する。期間内の他の欠測に対して、さらに古い日を追加しない。

比較1日で本日の実測がなければ前日を使う。各日の測定は1件でも1時間平均として使用する。複数日の差は日ごとに同じ重みで平均する。有効日数と測定件数、実際の比較期間を温度・湿度それぞれに残す。

実測を読む範囲は、基本の比較期間より1日前から固定締切まで。比較元の予報は各日の前日18:10に採用して保存済みのものを使う。

## 固定履歴の内容

`result_json`に以下を含め、結果だけでなく計算理由を追えるようにする。

- 元の予報・取得日時・採用地点・固定時の全設定とrevision。
- 各時間帯／項目の実際の比較開始日・終了日、本日使用または前日への切替。
- 各日の予報値、実測1時間平均、有効測定件数、差、採用／除外理由。
- 平均補正差、有効日数、使用測定件数、補正後の温湿度・飽差、湿度の0～100％調整。
- 6本の時間別蒸散量・日累積・必要水量・総時間・1回時間、欠測／未計算状態。
- 実測先未設定・実測取得失敗・データ不足の理由。植物設定が未入力なら、差と根拠は残し水量・時間を未計算とする。

## 画面とCSV

- 過去日は固定履歴だけを表示し、存在しない場合は「保存履歴なし」。過去の再計算・試算・履歴埋め戻しはしない。
- 今回取得した翌日の予報は、最初に固定履歴を表示する。補正日数・実測先を変えると翌日のみ試算し、画面に「試算中」を明示。「保存値に戻す」で固定履歴へ戻る。
- 試算が共有設定や固定履歴を変更することはない。設定保存は次回の予報採用から有効。revision不一致は409で止め、再読込みを案内する。
- 保存履歴CSVは当時の固定値・根拠を出力。試算CSVは翌日の試算だけを出力。温度／湿度で期間が異なる可能性があるため、それぞれの実際の期間をCSVに含める。
- 「本日未測定なら日数を減らす」計算・説明文は、1日前へ比較期間をずらす方式へ変更済み。
