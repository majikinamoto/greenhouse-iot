# アラート設定の最終更新日時

設定保存時（同じ内容の再保存も含む）と、有効設定の一括無効化時に専用列 `setting_updated_at` を日本時間で記録します。通知送信・復帰判定では変更しません。

「現在のアラート状態」と「現在有効なアラート設定」に、`最終更新：2026/10/26 14:30（日本時間）` の形式で表示します。既存設定の過去日時は推測せず「記録なし」と表示し、次回保存から記録します。

## 本番反映

コード変更とDB列追加の両方が必要です。今回、本番DBへの接続・変更は行っていません。

1. 本番DBをバックアップし、通知実行を含めたメンテナンス時間を確保してください。
2. 新しい `scripts/migrate-alert-schema.php` と `alert_settings.sql` を含む版を本番へ配置し、エンドポイントを利用再開する前に次を実行してください。

```sh
php scripts/migrate-alert-schema.php --apply
php check_alerts.php --diagnose
```

移行コマンドは不足する列を追加します。既存設定の日時はNULLのままで、自動的に過去日時を埋めません。すでに列があれば再追加しません。

DB列追加前の保存・一括無効化は新コードでは失敗するため、列追加までこれらの操作を行わないでください。

3. アラート設定を保存し、画面の最終更新日時を確認してください。同じ内容の再保存でも更新します。
4. 本番で実送信を伴う確認を行う場合は送信先を確認し、通知送信後も設定の最終更新日時が変わらないことを確認してください。

既存の `updated_at` は通知状態の更新でも変わるため、設定日時として使用しません。専用列に自動更新属性は付けません。

ローカル確認用：`node scripts/test-alert-setting-time.cjs`。本番DB移行・実データの表示確認は別途必要です。
