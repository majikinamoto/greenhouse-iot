# アラート診断

サーバーのプロジェクトディレクトリで実行します。

```sh
php check_alerts.php --diagnose
```

診断はCLI専用です。DBの読み取り専用トランザクションでテーブル構造、設定（無効・LINEも含む）、最新温度、通常処理での通知判定をJSON表示します。通知送信・状態更新・履歴追加・DB構造の変更は行いません。読み取り専用トランザクションを開始できない場合は終了します。引数の入力間違いでも通常通知処理には進みません。

`success` は必要なDB構造の参照と診断が完了したかを示し、配送の成功を示すものではありません。DB不足・診断エラーは終了コード1、引数間違いは2です。

| decision | 意味 |
| --- | --- |
| would_send_alert | 現在の通常処理なら異常通知の送信対象 |
| would_send_recovery | 現在の通常処理なら復帰通知の送信対象 |
| cooldown | 再通知待ち。残秒数も表示 |
| not_matched | 現在の送信条件に該当しない |
| disabled | 設定が無効 |
| unsupported_target | LINEなど、通知処理の対象外 |
| no_temperature | 対象の温度データがない |
| invalid_condition | 条件の設定が不正 |

`warnings` に古い測定値、通知先形式等を表示します。温度判定は通常処理と共通で、設定温度と同値も「以上・以下」に含みます。復帰通知に失敗した場合は異常状態を維持し、次回の通常処理で再試行します。PHPとDBの時刻・タイムゾーンも確認してください。測定時刻が1時間以上古い場合は診断上の注意として表示しますが、通常処理の判定は変更しません。

SMTP設定ファイルの存在、cURL・OpenSSLの有無は確認しますが、SMTP設定の内容・認証・接続・Webhookの有効性・配送・cronの稼働は確認しません。メールアドレス、Webhook URL、SMTP認証情報は出力しません。出力には利用者IDと計測値が含まれるため、保存する場合は公開領域外に置いてください。

判定ロジックのテスト（DB不要）：

```sh
php scripts/test-alert-diagnostics.php
```

本番通知を行う既存cronの引数は変更せず、診断は別途手動実行してください。

## 修正の反映と確認

今回の修正は、以上・以下の同値判定、復帰通知失敗時の再試行、SMTPメールの改行と日本語ヘッダーです。LINEは未対応と表示し、新しいLINE設定の保存は拒否します。既存のLINE設定は診断で検出し、Discordまたはメールへ変更してください。送信失敗があれば通常処理は終了コード1と`success: false`を返します。

本番反映後、先に診断を実行します。DB構造不足がある場合のみ、DBをバックアップして次の保守コマンドを実行します。これは診断とは異なりDB構造を変更します。既存列・既存設定・履歴は上書きせず、不足するテーブルと3列のみを追加します。既存テーブルのその他の不足列や型の不一致は自動修正しません。DDLはロールバックできないため、途中失敗時は原因を解消して再実行してください。

```sh
php scripts/migrate-alert-schema.php --apply
php check_alerts.php --diagnose
```

診断はcronの稼働や実際の配送成功を保証しません。定期実行ログと配送結果の確認が別途必要です。
